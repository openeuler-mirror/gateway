# BooMGateway 测试用例库

本目录是网关测试用例的唯一真相源。用例与角色解耦：用例内容只在 `cases/` 维护一份，各角色通过 `roles/` 下的索引视图取用。

## 目录结构

```
testcase/
├── README.md          本说明
├── cases/             共享用例库（按功能域分文件）
│   ├── 01-access.md     接入与认证（建 key、登录、鉴权、key 前缀）
│   ├── 02-invocation.md 模型调用（协议、流式、模型列表、兜底路由）
│   ├── 03-billing.md    计费对账（usage、单价、成本累计）
│   ├── 04-quota.md      配额与限流（RPM/TPM/终身额度、时段计划、恢复）
│   └── 05-admin.md      运维管理（key 管理、套餐分配、日志、热加载）
└── roles/             角色视图（用例引用，不重复内容）
    └── trial-user.md    前期试用者
```

## 用例格式

每条用例固定字段：

| 字段 | 说明 |
|------|------|
| ID | `<域前缀>-<序号>`，如 `ACC-03`。稳定锚点，角色视图按 ID 引用，**不得复用已删除用例的 ID** |
| 标题 | 一句话描述操作与预期 |
| 角色 | `admin` / `user` / `none`（无需认证）。标记执行该用例所需的最低权限 |
| 深度 | `smoke`（发版冒烟）/ `trial`（客户试用）/ `full`（全量回归）。一条用例可属多个深度，如 `smoke+trial` |
| 前置 | 执行前必须满足的条件（环境、数据、先前用例） |
| 步骤 | 可照做的操作指令 |
| 预期 | 可观察的结果判定（不涉及内部机制） |

## 标签取用规则

- **按角色取用例**：`grep "| admin" cases/*.md`（或直接看 roles/ 下对应视图）
- **按深度取用例**：`grep "| smoke" cases/*.md` 等
- **同一用例被多个角色视图引用是正常的**——内容只有一份
- 同一功能点对不同角色有不同预期（如日志可见范围）时，拆成独立用例而非一条用例写两套预期

## 角色视图格式

`roles/<role>.md` 包含：该角色的执行顺序、前置条件、用例 ID 清单（表格引用），以及执行反馈模板（勾选 + 问题时附请求 ID）。

## 与开发侧测试的关系

- `cases/` 中的用例面向**系统级黑盒测试**（真实网关 + 真实 DB + mock 上游），与 crates 内 316 个单元测试、`crates/boom-main/tests/` 的 e2e 互补
- 用例的"步骤/预期"即后续 AI 自动化测试的 spec 输入；角色标签即测试套件选择器
- hook 深度注入类用例（崩溃、溢出）不面向客户试用者，待全量阶段在 `cases/` 中补充并标记 `full`

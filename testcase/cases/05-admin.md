## ADM-01 创建 API key 并分配套餐

- **角色**：admin　**深度**：smoke+trial
- **前置**：已有一个可用套餐（无则先用 ADM-04 创建）。
- **步骤**：
  1. 面板 → Keys → 创建，填 `key_alias`、选择套餐、选择可访问模型
  2. 复制明文 key（只显示一次）交付试用者
  3. 试用者执行 ACC-01 验证可用
- **预期**：创建成功；key 按所选套餐的限额生效（可通过 QTA-01 抽查）；面板列表可见新 key 及其套餐。

## ADM-02 批量创建 key

- **角色**：admin　**深度**：trial
- **前置**：同 ADM-01。
- **步骤**：面板 → Keys → 批量创建（如 10 个），统一前缀 + 套餐；用其中 2 个抽样调用。
- **预期**：全部创建成功且独立可用；每个 key 的明文只显示一次；列表可按前缀识别同批 key；前缀校验规则与单条创建一致（ACC-05）。

## ADM-03 封禁与解封 key 即时生效

- **角色**：admin　**深度**：smoke+trial
- **前置**：存在一个正在使用中的 key。
- **步骤**：封禁 → 试用者调用（预期 403）→ 解封 → 再调用。
- **预期**：与 ACC-09 一致：封禁即时 403、解封即时恢复，全程无重启。面板中 key 状态标识正确。

## ADM-04 创建与修改套餐

- **角色**：admin　**深度**：trial
- **前置**：管理员登录。
- **步骤**：
  1. 创建套餐 `trial-basic`：RPM 5、并发 2
  2. 用 ADM-01 流程把某 key 分配到该套餐，验证限额生效
  3. 修改套餐为 RPM 100
  4. 该 key 再次调用验证
- **预期**：套餐创建、分配、修改均即时生效（同 QTA-06 逻辑，此用例从管理员操作视角覆盖）。

## ADM-05 新增模型部署后立即可路由

- **角色**：admin　**深度**：trial
- **前置**：管理员持有新 deployment 信息（如新 mock 上游地址）。
- **步骤**：
  1. 面板 → Models → 新增部署：`model_name: new-model`，指向新上游
  2. **不重启、不手动 reload**，试用者立即用 `new-model` 发起调用
- **预期**：新模型立即可路由（DB 写成功后直改内存，这是本网关的明确设计承诺）；`GET /v1/models` 同步可见。若面板同时提示 YAML 写入警告，记录警告内容（配置持久化状态需要知晓，但不影响当前服务）。

## ADM-06 配置热加载不中断服务

- **角色**：admin　**深度**：smoke+trial
- **前置**：管理员可直接改网关配置文件（或通过面板按钮）；试用者持有调用脚本可持续请求。
- **步骤**：
  1. 试用者启动持续调用（如每秒 1 次，观察是否中断）
  2. 管理员触发热加载（三选一：面板 Reload 按钮 / `kill -HUP <pid>` / `POST /admin/config/reload`）
  3. 观察调用连续性与当前限流计数
- **预期**：热加载期间**零请求失败**（无 5xx / 连接拒绝）；加载后配置生效；已消耗的限流计数不归零（试用者在加载前若已用 3/5 RPM，加载后仍按 3 继续，不重置成 0 也不清成 5）。

## ADM-07 面板查看全局统计与在途请求

- **角色**：admin　**深度**：trial
- **前置**：试用者正在执行流式调用（长响应进行中）。
- **步骤**：管理员打开 Stats / In-Flight 页面。
- **预期**：能看到按模型的请求量、成功率、token 统计；In-Flight 实时显示试用者正在进行的流式请求（模型、时长增长），流结束后该在途条目消失。

## ADM-08 Agent 类型统计正确

- **角色**：admin　**深度**：trial
- **前置**：试用者分别用 OpenAI 协议（INV-01）和 Anthropic 原生协议（INV-03，或 Claude Code）各发起若干调用。
- **步骤**：管理员查看面板的 Agent 类型统计（Debug / 统计区）。
- **预期**：两类调用的请求量与 token 分别计入对应类型（anthropic 原生 vs 匿名/OpenAI 兼容），比例与实际调用次数相符；分钟粒度曲线在调用时段有值。

## ADM-09 离群样本扫描可用

- **角色**：admin　**深度**：trial
- **前置**：已积累一定量请求日志（前面用例自然产生）。
- **步骤**：管理员打开离群分析，按 key 维度扫描最近 1 天。
- **预期**：正常情况下无异常条目或仅少量轻偏离；人为制造一个异常（如某 key 连续调用慢模型形成延迟离群）后能出现在结果中并排在前列；维度可切换（key / 模型 / 节点 / 团队）。

## ADM-10 管理员只能看到全局日志的合理范围

- **角色**：admin　**深度**：trial
- **前置**：多个试用 key 已产生日志。
- **步骤**：管理员按不同 key、模型、时间组合过滤日志；试用者（用户面板）核对自身可见范围。
- **预期**：管理员可见全部请求日志（全局视角）；普通用户仅见自己 key 的记录（与 BIL-06 / ACC-08 形成权限闭环：全局可见 vs 隔离可见）；过滤组合结果准确无串数据。

# 04 配额与限流（Quota & Rate Limit）

覆盖：RPM/TPM/并发窗口限额、终身额度、时段计划、超限响应、恢复、面板感知。

试用者视角的核心诉求：撞限额时**得到明确、可预期**的响应，且**恢复后自动可用**，全程能从面板看到自己的额度状态。

| ID | 标题 | 角色 | 深度 |
|----|------|------|------|
| QTA-01 | 超出 RPM 得到 429 且错误信息含限额值 | user | trial |
| QTA-02 | 窗口滑过后自动恢复 | user | trial |
| QTA-03 | 超出 TPM 得到 429 | user | trial |
| QTA-04 | 终身 token 额度耗尽得到明确拒绝 | user | trial |
| QTA-05 | 面板显示当前额度与倒计时 | user | trial |
| QTA-06 | 套餐调整后新限额立即生效 | admin | trial |
| QTA-07 | 重置限额窗口后立即可用 | admin | trial |
| QTA-08 | 时段计划切换限额 | admin | trial |

---

## QTA-01 超出 RPM 得到 429 且错误信息含限额值

- **角色**：user　**深度**：trial
- **前置**：管理员为试用 key 分配了低 RPM 套餐（如 5 RPM，方便测试）；试用者知晓限额值。
- **步骤**：快速连续发起调用（超过限额，如 1 分钟内 7 次），记录第 6 次起的响应。
- **预期**：超限请求返回 429；错误信息包含限额值与重试提示（如"5 请求/分钟"），`error.type` 为 `rate_limit_exceeded`；未超限的前 5 次（或按套餐配置数）均为 200。**注意配额倍率**：若所用模型配置了 `quota_count_ratio` > 1，每次请求消耗多个配额，实际可成功的次数相应减少——按管理员告知的倍率验证。

## QTA-02 窗口滑过后自动恢复

- **角色**：user　**深度**：trial
- **前置**：QTA-01 已触发 429。
- **步骤**：等待 1 分钟（限额窗口周期），再次发起调用。
- **预期**：无需任何人工干预，调用自动恢复 200。

## QTA-03 超出 TPM 得到 429

- **角色**：user　**深度**：trial
- **前置**：管理员为 key 分配了低 TPM 套餐（如 1K TPM）；模型可产生足量 token。
- **步骤**：发起带较长输入（数千字符）的调用，使单次或数次请求的 token 之和超过 TPM。
- **预期**：超限后返回 429，错误信息指明 token 维度限额；同样在窗口滑过后自动恢复。

## QTA-04 终身 token 额度耗尽得到明确拒绝

- **角色**：user　**深度**：trial
- **前置**：管理员为 key 设置极低的终身 token 额度（如 100 token）。
- **步骤**：持续调用直到额度耗尽，观察耗尽后的响应；之后在面板查看该 key 状态。
- **预期**：耗尽后请求被拒，错误信息明确指向终身额度（而非笼统 429），提示额度已用尽需联系管理员；面板显示该 key 额度已满。管理员提高额度（见 QTA-06）后恢复可用。

## QTA-05 面板显示当前额度与倒计时

- **角色**：user　**深度**：trial
- **前置**：QTA-01~04 过程中任一状态；试用者可登录用户面板。
- **步骤**：在正常、接近超限、已超限三种状态下分别刷新用户面板的 Usage 页。
- **预期**：实时显示当前窗口已用 / 限额（进度条）；接近超限时进度条高比例；已超限状态可辨；若套餐有窗口重置周期，显示倒计时且倒计时走动。

## QTA-06 套餐调整后新限额立即生效

- **角色**：admin　**深度**：trial
- **前置**：试用 key 当前为低限额套餐（QTA-01 配置）。
- **步骤**：
  1. 试用者先触发一次 429（确认旧限额生效）
  2. 管理员在面板把该 key 调整为高限额套餐（如 100 RPM）
  3. 试用者立即再次调用（不等待原窗口、不重启网关）
- **预期**：调整后立即按新限额放行；用户面板 Usage 同步显示新限额。**验证"改套餐不需要重启"这一运维关键承诺**。

## QTA-07 重置限额窗口后立即可用

- **角色**：admin　**深度**：trial
- **前置**：试用 key 处于 429 超限状态。
- **步骤**：管理员在面板执行该 key 的限额重置；试用者立即调用。
- **预期**：重置后立即恢复 200，无需等待窗口自然滑过。

## QTA-08 时段计划切换限额

- **角色**：admin　**深度**：trial
- **前置**：管理员为套餐配置两个时段（如工作时段 100 RPM / 其余时段 5 RPM），与试用者约定在切换点前后测试。
- **步骤**：在切换点前用低限额验证（快速触发 429）；切换点过后立即重复同样的调用强度。
- **预期**：切换点后按高限额放行（不再 429）；面板 Usage 显示的限额值同步变化。**注意**：时段计划支持跨午夜配置（如 21:00-9:00），选切换点尽量避开午夜以简化验证。

# 03 计费对账（Billing）

覆盖：usage 正确性、单价核算、成本累计、KV 命中计费、对账导出。

计费是试用的命门：试用者最需要验证"我用的 token 数和我算的能对上，费用能复核"。

| ID | 标题 | 角色 | 深度 |
|----|------|------|------|
| BIL-01 | 单次请求 usage 与响应一致 | user | trial |
| BIL-02 | 面板日志 usage 与响应一致 | user | trial |
| BIL-03 | 按模型单价核算费用 | user | trial |
| BIL-04 | token 累计量随调用正确增长 | user | trial |
| BIL-05 | 成本累计与单价 × token 一致 | user | trial |
| BIL-06 | 日志按时间与模型过滤对账 | admin | trial |

---

## BIL-01 单次请求 usage 与响应一致

- **角色**：user　**深度**：trial
- **前置**：同 INV-01。
- **步骤**：发起一次非流式请求，固定一条简短消息（如 `"数到5"`）；记录响应中 `usage` 三项。
- **预期**：`prompt_tokens` 与消息长数量级相符（简短中文约 3~10 token）；`total_tokens = prompt_tokens + completion_tokens`。流式请求重复一次，末分片的 usage 同样满足该关系。

## BIL-02 面板日志 usage 与响应一致

- **角色**：user　**深度**：trial
- **前置**：BIL-01 已执行；试用者可登录用户面板。
- **步骤**：打开用户面板 → 日志，找到 BIL-01 那次请求的记录。
- **预期**：面板记录的模型、流式标记、input/output token 与响应中的 usage 逐项一致；记录时间与实际调用时间相符。**若发现不一致，记下请求 ID 并在反馈中附上**（这是计费可信度的关键用例）。

## BIL-03 按模型单价核算费用

- **角色**：user　**深度**：trial
- **前置**：管理员告知试用者所用模型的单价（USD / 百万 token，输入价与输出价）；同 BIL-01。
- **步骤**：
  1. 记录一次调用的 `usage.prompt_tokens` 与 `usage.completion_tokens`
  2. 手工计算：`费用 = prompt_tokens/1M × 输入单价 + completion_tokens/1M × 输出单价`
  3. 与面板该次请求的成本字段（或团队统计增量）比对
- **预期**：手工核算与面板显示一致（允许四舍五入级误差）。

## BIL-04 token 累计量随调用正确增长

- **角色**：user　**深度**：trial
- **前置**：记录面板当前 token 累计基数；确定一段时间内无其他人使用同一 key。
- **步骤**：用同一 key 连续发起 3 次调用（各记录 usage），然后刷新面板统计。
- **预期**：累计输入 token 增量 = 3 次 `prompt_tokens` 之和；输出同理。**注意**：此期间不要并行跑其他用例，否则增量混入他人用量。

## BIL-05 成本累计与单价 × token 一致

- **角色**：user　**深度**：trial
- **前置**：BIL-04 通过；模型单价已知。
- **步骤**：在 BIL-04 的基础上，用同样的方法核对成本累计增量 = 3 次调用费用之和。
- **预期**：一致（允许分币级误差）。若试用模型支持 KV 缓存命中且命中时按 cached 单价计费，尝试重复发送相同前缀的请求，观察后续请求成本低于首次（单价差生效）。

## BIL-06 日志按时间与模型过滤对账

- **角色**：admin　**深度**：trial
- **前置**：试用者已完成 BIL-01~05；管理员登录管理面板。
- **步骤**：
  1. 打开管理面板 → Logs，按试用者的 key（或前缀）过滤
  2. 叠加时间范围过滤（今天 / 最近 1 小时）
  3. 叠加模型过滤
  4. 汇总该过滤结果
- **预期**：过滤结果只含该 key 的请求；条数与试用者实际调用次数一致；token 合计与试用者 BIL-04 记录的增量一致。**这是面向客户运维的对账入口，过滤组合必须准确**。

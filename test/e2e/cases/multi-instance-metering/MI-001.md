## 目的
双实例各自服务已知用量后，DB 累计值与客户端观测 usage 之和精确相等（收敛不丢失）
## 前置
G-base 双实例就绪；run 唯一 fixture key（无 plan——记账不受 plan 门控，每次 run 全新 DB 天然唯一）
## 步骤
1. gw-a 发 10 请求、gw-b 发 5 请求（同 key 同 model），逐条记录响应 usage
2. poll boom_quota_delta 直到 gw-a/gw-b 各出现新 seq 水位行（≤95s）
3. 读 boom_rate_limit_cumulative 该 key 的累计值
## 预期
- cumulative tokens == Σ 响应 usage.total_tokens（精确相等）
- 水位行 seq 单调递增，两实例各推各的命名空间
